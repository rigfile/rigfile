# Target: Gemini CLI

**Date checked:** 2026-09-26. Sources: `google-gemini/gemini-cli` docs on GitHub (`docs/reference/configuration.md`, `docs/cli/gemini-md.md`, `docs/cli/custom-commands.md`), fetched as raw markdown through a summarising fetcher; anything not returned is marked **UNVERIFIED**. Nothing was read from a real `~/.gemini`.

| Category | Verified facts | Adapter decision |
|---|---|---|
| Config root | `~/.gemini` (`%USERPROFILE%\.gemini` on Windows by the same convention: **UNVERIFIED**); `GEMINI_CLI_HOME` overrides "the root directory for user-level configuration and storage". | `${GEMINI_CLI_HOME:-~/.gemini}`. |
| Settings | User `~/.gemini/settings.json`, project `.gemini/settings.json`, system `/etc/gemini-cli/settings.json` (Linux), `/Library/Application Support/GeminiCli/settings.json` (macOS), `C:\ProgramData\gemini-cli\settings.json` (Windows). Precedence: defaults → system defaults → user → project → system → env vars → CLI args. JSON; strings expand `$VAR`, `${VAR}`, `${VAR:-default}`. | Write user `settings.json` with the layout-preserving JSON editor (`internal/jsonedit`). |
| Instructions | `GEMINI.md`: global `~/.gemini/GEMINI.md`, workspace and parent dirs, plus just-in-time subdirectory files; `@file.md` imports; file name configurable via `context.fileName` (may be an array incl. `AGENTS.md`). | Marked section in `~/.gemini/GEMINI.md` (same splice mechanism as Claude Code). |
| MCP servers | `mcpServers` object in settings.json; keys per server: `command`, `args`, `env`, `cwd`, `url`, `httpUrl`, `headers`, `timeout`, `trust`, `includeTools`, `excludeTools`. `url` vs `httpUrl` (SSE vs streamable HTTP) semantics **UNVERIFIED**. | stdio via the `rigfile exec` wrapper (same as Claude Code); remote as `httpUrl` (streamable HTTP) — **UNVERIFIED** which key is right for canonical `transport: http`; test with a real CLI in S3-M10. |
| Commands | `~/.gemini/commands/**/*.toml` (user) and `.gemini/commands/` (project, overrides); required key `prompt`, optional `description`; subdirectories namespace with `:` (`git/commit.toml` → `/git:commit`); `{{args}}`, `!{shell}`, `@{file}`. | Canonical `commands:` (Markdown) → TOML with `prompt` = the Markdown body, `description` from frontmatter. |
| Hooks | A hooks system exists: events `BeforeTool`, `AfterTool`, `BeforeAgent`, `AfterAgent`, `Notification`, `SessionStart`, `SessionEnd`, `PreCompress`, `BeforeModel`, `AfterModel`, `BeforeToolSelection`. **The settings shape and the stdin/stdout contract were not readable: UNVERIFIED.** | Hooks are skipped with a visible note until the contract is verified (S3-M10 live check); base-secure falls back to permissions + instructions. |
| Permissions / tools | `tools.allowed`, `tools.exclude`, `tools.core`, `tools.confirmationRequired`; approval modes `default`, `auto_edit`, `plan`, `yolo` (YOLO only via CLI flag); sandbox via `tools.sandbox` / `GEMINI_SANDBOX` (Docker, Podman, LXC). Rule syntax for `tools.exclude` entries (e.g. `run_shell_command(rm)`) **UNVERIFIED**. | base-secure maps deny to `tools.exclude` only for shell-command entries whose syntax is verified; otherwise "instructions only". |
| Skills, subagents | Not found in the pages read. | Skipped with a note ("Gemini CLI: skills/subagents not supported"). |
| Credentials | Location of OAuth tokens **not documented on the pages read** (UNVERIFIED; commonly `~/.gemini/oauth_creds.json` and an `.env` file). | base-secure denies reads of `~/.gemini/oauth_creds.json` and `~/.gemini/.env` defensively (a deny for a missing file is harmless). |
| OS support | Node.js CLI: macOS, Linux, Windows (**UNVERIFIED** on the pages read). | Treated as available on all three. |
