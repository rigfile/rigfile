## Design calls (decided by my recommendation)

1. **Signing is Sigstore keyless, bring-your-own-bundle.** Rigfile *verifies*; it does not implement OIDC signing. A publisher signs the tarball with `cosign sign-blob --bundle` (locally with a browser OIDC login, or in GitHub Actions with the workflow identity) and passes the bundle to `rigfile publish --sign-bundle`. The registry stores the bundle and shows the signer; the CLI **re-verifies locally** (it never trusts the registry's verdict) against the Sigstore trusted root and an identity policy, and the lock records issuer and subject.
2. **Identity policy: the signer must be the publisher.** For a GitHub-identity signature, the certificate's subject must belong to the publisher's GitHub account: either the publisher's own GitHub Actions workflow (`https://github.com/<login>/...`) or an OIDC identity whose email/login maps to that account. Anything else is "signed, but not by this publisher" and is shown as such, never as verified.
3. **Signatures are required only where it matters:** for a rig whose stars pass a configurable threshold (the plan's "2FA for popular rigs" — GitHub's API does not reveal another user's 2FA status, and GitHub already requires 2FA for contributors, so the enforceable proxy is "popular rigs must be signed by the publisher's GitHub identity and the publisher must be verified"). Below the threshold signing is optional and shown as a badge.
4. **Verified publisher = an administrator's decision**, recorded with a note (domain, organisation, or a person known to the operator). It is a badge, not an automatic check.
5. **Static analysis informs, it rarely blocks.** Findings have three levels (notice, caution, danger), are shown on the rig page and on the pull screen, and never contain script contents. Only a short list of near-certain patterns puts a version in **held** review (below); everything else is information for the person approving the plan.
6. **A moderation queue (`held`)**: a version whose scan finds danger-level analysis results, or a new public name confusably close to a popular rig, is *held*: invisible to everyone but the owner and admins until an administrator releases or rejects it (web page `/admin` and operator tools).
7. **MCP packages are looked up in OSV** (npm and PyPI, exact pinned versions): known malicious packages (`MAL-`) reject; known vulnerabilities warn with ids and severity. If OSV is unreachable the scan says the check was unavailable; it does not pass silently and does not fail the upload.
8. **Typosquat detection is a warning system**, not a gate (except the `held` case above): edit distance, delimiter and confusable-character normalisation against existing public rigs and popular owners, shown to the publisher at upload and to the puller on the plan screen.
9. **Reputation signals** on the pull screen: age, versions, stars, publisher account age and rig count, verified badge, signature status, analysis summary, yank/removal history. Signals are facts with numbers, not a score.
